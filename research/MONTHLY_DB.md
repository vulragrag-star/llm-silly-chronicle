# MONTHLY MODEL REPORT DATABASE

Database-first research layer for *LLM Silly Chronicle* (模型酒馆编年史).

## What this is

Month-by-month high-visibility AI model/product/tool ledger (global + CN) from **2022-01** through **2026-09**.

Used later for chapter writing and character casting — **not** novel prose.

## Layout

| Path | Purpose |
|---|---|
| `data/models_index.jsonl` | One JSON object per unique entity |
| `data/monthly/YYYY-MM.json` | Per-month pack |
| `research/MONTHLY_DB.md` | This file — coverage stats & usage |
| `scripts/build_monthly_db.py` | Regenerator (+ `extend_months.py`) |

### Monthly JSON schema

```json
{
  "month": "YYYY-MM",
  "headline": "...",
  "confidence": "high|medium|low|stub",
  "models_released_or_updated": [{"id","what_changed","heat"}],
  "events": [{"title","summary","links","date?"}],
  "memes_and_discourse": ["tag: note"],
  "community_sentiment": "...",
  "cast_candidates": ["entity-id"],
  "notes": "optional uncertainty"
}
```

`heat` is 1–5 subjective community visibility for chronicle casting.

## How to use

1. Before writing `chapters/YYYY-MM.md`, read `data/monthly/YYYY-MM.json` + prior month cast.
2. Pick cast from `cast_candidates` and high-`heat` releases; do not spoil future months.
3. Verify `confidence: medium/low` and any `notes` against primary sources before locking canon.
4. Extend: add a line via `m(...)` in `scripts/build_monthly_db.py`, add month via `extend_months.py` or MONTHS[...], re-run the script.
5. Rebuild: `python3 scripts/build_monthly_db.py` from repo root / scripts dir.

## Source policy

- Prefer official lab blogs, GitHub releases, Wikipedia, Reuters/PR for CN approvals.
- Aggregators (BenchmarkList, GPT0X, AI Release Tracker) used for cadence — mark uncertain for 2025–2026.
- This DB is a research scaffold, not a legal/compliance record.
